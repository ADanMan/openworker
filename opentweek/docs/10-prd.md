# opentweek: продуктовые требования

Актуальность: 27 сентября 2026 года.

## 1. Проблема

Человек планирует неделю задачами, а не встречами. Календари с сеткой часов (Google Calendar, Outlook) навязывают время там, где его нет. Списки дел (Todoist, TickTick) прячут неделю за фильтрами. Tweek решает это «бумажной неделей», но:

- повторы, подзадачи, вложения, напоминания, месяц, темы и скрытие выполненных доступны только в платном Premium ($5.99 в месяц или $49.99 в год, по данным поисковой выдачи tweek.so);
- данные живут на чужом сервере, экспорта в открытый формат с полной структурой нет;
- офлайн-режим ограничен.

Сейчас задача решается бесплатным Tweek с ограничениями (3 списка, 2 календаря, 2 цвета, без повторов) либо бумажным ежедневником.

## 2. Пользователи и роли

- **Автор проекта.** Один человек, планирует личное и рабочее на неделю. Основное устройство — Android-телефон, иногда ноутбук. Пишет по-русски.
- **Человек из open-source.** Ставит веб-версию на свой хостинг или собирает APK сам. Хочет, чтобы сборка не требовала Android Studio.

Ролей внутри приложения нет: один пользователь на устройство.

## 3. Сценарии

По убыванию ценности:

1. Пользователь хочет на ходу записать задачу на конкретный день недели одной строкой, чтобы не держать её в голове.
2. Пользователь хочет получить напоминание в заданное время, даже если приложение закрыто, чтобы не пропустить дело.
3. Пользователь хочет завести повторяющуюся задачу (каждый будний день, раз в две недели, 15-го числа), чтобы не переписывать её каждую неделю.
4. Пользователь хочет перетащить невыполненную задачу на другой день или в «Когда-нибудь», чтобы неделя отражала реальный план.
5. Пользователь хочет видеть встречи из Google Calendar рядом с задачами, чтобы планировать вокруг них.
6. Пользователь хочет разбить задачу на подзадачи и приложить файл или фото, чтобы всё нужное было в одном месте.
7. Пользователь хочет раздельные календари «Личное» и «Работа», чтобы не смешивать контексты.
8. Пользователь хочет выгрузить все данные одним файлом и восстановить их на другом устройстве, чтобы не зависеть от приложения.
9. Пользователь хочет отправить задачу другому человеку, чтобы тот добавил её себе.

## 4. Метрики успеха

Продукт личный, аналитики нет и не будет (см. не-цели). Метрики снимаются вручную:

| Метрика | Цель | Как замерить |
|---|---|---|
| Время записи задачи с холодного старта приложения | до 5 с | Секундомер, 10 попыток на телефоне |
| Доля напоминаний, пришедших вовремя (±1 мин) | 100% за неделю | Журнал: 7 дней по 3 напоминания, отмечать факт прихода |
| Потери данных | 0 | Сравнение экспорта JSON до и после обновления APK |
| Время сборки APK на чистой Ubuntu 24.04 | до 5 мин, включая `apt-get install` | `time android/build.sh` в свежем контейнере |
| Размер APK | до 1 МБ | `ls -l releases/` |

## 5. Не-цели

- **Синхронизация и совместная работа в 1.x.** Нужен сервер или P2P-слой, это отдельный продукт по объёму. Перенесено в 2.0, см. ADR-0009.
- **Сетка часов и тайм-блокинг.** Это другой продукт; у opentweek есть только время напоминания.
- **Аналитика, телеметрия, крэш-репортинг.** Противоречат обещанию «данные не покидают устройство».
- **Публикация в Google Play.** Требует приватного ключа, политики конфиденциальности и прохождения ревью `USE_EXACT_ALARM`. Пока распространяем APK из репозитория.
- **iOS-приложение.** Нет устройства для проверки; веб-версия ставится на iOS как PWA.
- **AI-подсказки задач (аналог Tweek GPT).** Требуют внешнего API и ключа, противоречат локальности.

## 6. Ограничения

- Один разработчик, вечера и выходные.
- Сборка должна работать без Google Maven и `dl.google.com`: в среде разработки они закрыты сетевой политикой. GitHub Actions на аккаунте не запускаются.
- Все зависимости под MIT, Apache-2.0, BSD или MPL-2.0; GPL и AGPL исключены, потому что проект под MIT.
- Минимальная версия Android — 7.0 (API 24): системный WebView на ней обновляется через Play Store.

## 7. Риски продукта

| Риск | Вероятность | Что делаем |
|---|---|---|
| Прошивка производителя убивает будильники, напоминания не приходят | Средняя | `setExactAndAllowWhileIdle` + `USE_EXACT_ALARM`; в 1.1 добавить подсказку про исключение из энергосбережения (T-106) |
| Пользователь удаляет APK и теряет все данные | Средняя | Напоминание о бэкапе в настройках; в 1.1 автобэкап в выбранную папку (T-108) |
| Системный WebView слишком старый для CSS `:has()` и `color-mix()` | Низкая | Деградация только внешнего вида; минимум API 24, WebView обновляется из Play Store |
| Ключ подписи из репозитория использует кто-то чужой, чтобы подменить обновление | Низкая для личного APK | Задокументировано в ADR-0006; перед публикацией ключ заменяется |
| Сравнение с Tweek устареет | Высокая | Таблица в README помечена датой |
