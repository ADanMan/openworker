# opentweek: план работ 1.0.x–2.0

Актуальность: 27 сентября 2026 года.

|---|---|---|---|
| E1 Полевые испытания | APK подтверждён на своём телефоне, найденные дефекты закрыты | — | 2 |

## 2. Порядок работ

```text
E1 Полевые испытания (1.0.1)
 → E2 Надёжность напоминаний
 → E3 Сохранность данных          (1.1)
 → E5 Порядок и производительность
 → E4 Виджет «Сегодня»            (1.2)
 → E6 Синхронизация               (2.0)
```

## 3. Критический путь

E1 блокирует всё Android-специфичное. Пока APK не запускался на телефоне, любая работа в `android/` строится на непроверенном фундаменте. E3 блокирует E6: синхронизация без надёжного бэкапа рискует размножить повреждённые данные на два устройства.

## 4. Вертикальные срезы

- E1: установить APK → пройти смоук → исправить → собрать 1.0.1 → повторить смоук. Каждая итерация заканчивается APK в `releases/`.
- E2: подсказка в настройках + кнопка, открывающая системный экран энергосбережения → проверка на телефоне ночью с выключенным экраном.
- E3: автобэкап в папку, выбранную через `ACTION_OPEN_DOCUMENT_TREE`, раз в сутки → восстановление на чистой установке.
- E4: виджет с тремя строками из того же расписания, что уходит в `setReminders` → обновление по `AlarmManager` в полночь.
- E6: сначала файл в облачной папке (merge по `updatedAt`) на двух устройствах, потом решение о Yjs.

## 5. Риски исполнения

| Где застрять | Признак | План Б |
|---|---|---|
| Рефлексия в `Reminders.java` не срабатывает на Android 14/15 | Нет уведомлений при выданном разрешении | Лог `adb logcat`, поправить имя метода; в крайнем случае собрать с Gradle в среде с доступом к Google Maven |
| Виджет требует `RemoteViews` и новых ресурсов, которые `aapt` 1 не соберёт | Ошибки `aapt` на атрибутах новее API 23 | Ограничиться атрибутами API 23, либо отложить E4 |
| Синхронизация разрастается | E6 дольше 15 дней | Остановиться на файловой синхронизации без реального времени |
