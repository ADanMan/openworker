# opentweek: runbook

Актуальность: 27 сентября 2026 года.

## 1. Состав системы

| Компонент | Где | Как называется |
|---|---|---|
| Исходники | `github.com/ADanMan/openworker`, папка `opentweek/`, ветка `claude/opentweek-calendar-pro-gjczbp` | — |
| APK | `opentweek/releases/opentweek-X.Y.Z.apk` + `.sha256` | пакет `app.opentweek` |
| Данные на телефоне | IndexedDB WebView в каталоге приложения | origin `https://app.opentweek.local` |
| Расписание напоминаний | `SharedPreferences` `reminders`, ключ `schedule` | — |
| Веб-версия | `opentweek/dist/` после `npm run build` | любой статический хостинг |
| Логи на телефоне | `adb logcat` | теги `chromium`, `AndroidRuntime` |

## 2. Сборка и публикация

Среда: Ubuntu 24.04, Node 22.

```bash
sudo apt-get install -y aapt dalvik-exchange zipalign apksigner android-sdk-platform-23 openjdk-21-jdk-headless
cd opentweek
npm ci
npm run lint && npm test && npm run build
npm version 1.0.1 --no-git-tag-version        # новая версия; versionCode = 10001
android/build.sh                               # → releases/opentweek-1.0.1.apk
aapt dump badging releases/opentweek-1.0.1.apk | head -3
git add releases package.json package-lock.json docs/41-changelog.md docs/40-release-notes.md
git commit -m "opentweek 1.0.1"
git push -u origin claude/opentweek-calendar-pro-gjczbp
```

Установка на телефон (Android 8+ требует разрешения «Установка неизвестных приложений» для того приложения, из которого открыт APK):

1. Открыть в Chrome на телефоне прямую ссылку:  
   https://raw.githubusercontent.com/ADanMan/openworker/claude/opentweek-calendar-pro-gjczbp/opentweek/releases/opentweek-1.1.0.apk
2. Chrome скачает файл; в уведомлении или в «Загрузках» Chrome нажать на `opentweek-1.1.0.apk`.
3. На запрос «Установка из этого источника запрещена» → «Настройки» → включить «Разрешить из этого источника» для Chrome → назад → «Установить».

Файлы, открытые из мессенджеров и чат-приложений, часто не доходят до установщика: у этих приложений нет разрешения на установку пакетов, и кнопки «Установить» нет. В этом случае открыть файл через «Файлы» (Files by Google): «Загрузки» → APK → разрешить установку для «Файлов».

Либо по кабелю:

```bash
adb install -r opentweek/releases/opentweek-1.0.1.apk
```

## 3. Смоук после установки

1. Приложение открывается, видна текущая неделя, сегодняшний день выделен цветом.
2. Запись «тест 1» в сегодняшний день появляется строкой, сохраняется после закрытия из недавних и повторного открытия.
3. Настройки → «Уведомления о напоминаниях» → системный запрос → «Разрешить» → чекбокс включён.
4. Задача с напоминанием через 2 минуты → закрыть приложение → уведомление пришло вовремя; тап открывает задачу.
5. Повтор «Каждый день» → на следующей неделе строки на всех днях; отметка одного дня не отмечает другие.
6. Свайп влево → следующая неделя; «Сегодня» → возврат.
7. «Назад» при открытой карточке закрывает её; повторное «Назад» сворачивает приложение.
8. Настройки → «Экспорт копии (.json)» → системный диалог → файл сохранён, тост «Сохранено».
9. Подписка на ICS-ссылку Google Calendar → статус «событий: N», события видны на неделе.
10. Язык → English → интерфейс переключился без перезапуска.
11. Микрофон → «завтра в 9 позвонить маме» → задача на завтра с напоминанием 09:00, тост «Добавлено».
12. Долгое нажатие на иконку → «Голосовая задача» и «Новая задача» → оба открывают нужный режим.
13. Chrome → «Поделиться» → opentweek → текст стал задачей.

## 4. Откат

Android не устанавливает APK с меньшим `versionCode` поверх установленного. Откат возможен только через удаление, а удаление стирает данные. Поэтому порядок строгий:

1. В текущей версии: Настройки → «Экспорт копии (.json)» → сохранить в «Загрузки». Проверить, что файл не пустой (больше 100 байт).
2. Достать прошлый APK. Все версии лежат в `releases/`; если файл удалён, взять из истории:
   ```bash
   git log --oneline -- opentweek/releases/
   git show <commit>:opentweek/releases/opentweek-1.0.0.apk > /tmp/opentweek-1.0.0.apk
   sha256sum /tmp/opentweek-1.0.0.apk   # сверить с .sha256 из того же коммита
   ```
3. Удалить приложение: Настройки Android → Приложения → opentweek → Удалить, или `adb uninstall app.opentweek`.
4. Установить прошлый APK.
5. Настройки → «Восстановить копию» → выбрать файл из шага 1.
6. Пройти смоук, пункты 1, 2, 3.

Точка невозврата: шаг 3. Без файла из шага 1 данные после него не восстановить. Формат бэкапа версии 1 одинаков в 0.1.0 и 1.0.0, поэтому копия из новой версии читается старой.

## 5. Типовые сбои

| Симптом | Вероятная причина | Что сделать | Как убедиться |
|---|---|---|---|
| APK не открывается, кнопки «Установить» нет | Файл открыт из приложения без права на установку пакетов (чат, мессенджер) | Скачать по прямой ссылке в Chrome или открыть через «Файлы»; разрешить «Установку неизвестных приложений» для этого приложения | Появился экран установщика с кнопкой «Установить» |
| «Приложение не установлено» при обновлении | APK подписан другим ключом | Проверить `apksigner verify --print-certs`: SHA-256 должен быть `074199…3ace` | Сертификаты совпали, установка прошла |
| «Приложение не установлено», ключ тот же | `versionCode` не больше установленного | Поднять версию в `package.json`, пересобрать | `aapt dump badging` показывает больший `versionCode` |
| Белый экран при запуске | Бандл не попал в `assets/www` или JS упал в старом WebView | `unzip -l APK \| grep www/index.html`; `adb logcat -s chromium:V` | `index.html` есть, в логе нет `Uncaught` |
| Напоминания не приходят | Уведомления выключены, или прошивка убивает будильники | Проверить разрешение уведомлений; исключить из энергосбережения; `adb shell dumpsys alarm \| grep app.opentweek` | В `dumpsys alarm` есть будильники `app.opentweek` |
| После перезагрузки нет напоминаний | `BootReceiver` не сработал до первого разблокирования | Открыть приложение один раз: расписание перезапишется | `dumpsys alarm` снова показывает будильники |
| Подписка: «HTTP 404» | Ссылка неверная или сброшена в Google | Взять новую «Секретную ссылку в формате iCal» | Статус «событий: N» |
| Задачи пропали после обновления WebView | Сброс данных WebView (не наблюдалось, T-104) | Восстановить из последнего бэкапа, раздел 7 | Задачи на месте |
| Кнопки микрофона нет | Нет приложения распознавания речи (`voiceAvailable()` = false) | Установить или включить приложение Google | Кнопка появилась после перезапуска |
| Ярлыков на иконке нет | Лаунчер без поддержки ярлыков или Android ниже 7.1 | Проверить в Pixel Launcher или One UI | Ярлыки видны |
| `build.sh`: `missing tool` | Не установлены пакеты | Команда `apt-get install` из раздела 2 | `build.sh` доходит до `==> ../releases/…` |
| `build.sh`: ошибка `aapt` про атрибут | Атрибут новее API 23 в манифесте или ресурсах | Убрать атрибут или вынести его в рефлексию в Java | Сборка проходит |

## 6. Диагностика

```bash
adb logcat -c && adb logcat -s chromium:V AndroidRuntime:E ActivityManager:I | grep -i -E "opentweek|Uncaught|FATAL"
adb shell dumpsys alarm | grep -A3 app.opentweek          # запланированные будильники
adb shell dumpsys notification | grep -A2 app.opentweek   # каналы и разрешение
chrome://inspect                                           # WebView отлаживается, только если приложение debuggable; release-сборка — нет
```

Для отладки JS в WebView используйте веб-версию (`npm run dev`) с имитацией моста: `addInitScript` в Playwright, пример в сквозных тестах из `32-test-plan.md`.

## 7. Данные

- Снять бэкап: Настройки → Данные → «Экспорт копии (.json)». Около 1 КБ на 5 задач без вложений; вложения входят в файл в base64 и увеличивают его примерно на треть от размера файлов.
- Восстановить: «Восстановить копию» → выбрать файл → подтвердить. Заменяет все данные. Занимает меньше 2 с на 1000 задач (оценка, не замерено).
- Перенос между устройствами: экспорт на одном, восстановление на другом.

## 8. Внешние зависимости

| Зависимость | Что будет при недоступности | Что делать |
|---|---|---|
| Google Calendar ICS | Лента не обновится, останется кэш последней загрузки | Ничего; повтор через 30 минут или кнопка «Обновить» |
| Системный WebView (Play Store) | Старый WebView может не поддерживать `:has()` и `color-mix()`: страдает оформление, не данные | Обновить «Android System WebView» |
| Архив Ubuntu (сборка) | Нельзя поставить инструменты сборки | Кэшировать `.deb` из `/var/cache/apt/archives` рядом с проектом |
| GitHub | Нельзя скачать APK | Передать файл по кабелю: `adb install` |
