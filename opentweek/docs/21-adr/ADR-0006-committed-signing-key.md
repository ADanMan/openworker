# ADR-0006: Ключ подписи APK хранится в репозитории

Дата: 27 сентября 2026 года
Статус: Accepted

## Контекст

Android ставит обновление поверх установленного приложения, только если оно подписано тем же ключом. Иначе приложение приходится удалять вместе с данными. CI с секретами недоступен (GitHub Actions не работают), сборка идёт в эфемерных контейнерах.

## Рассмотренные варианты

- Новый ключ на каждую сборку — ничего не хранить / каждое обновление стирает данные;
- Ключ в секретах CI — правильно / CI недоступен;
- Ключ `android/opentweek.keystore` в репозитории, пароль `opentweek` — обновления встают поверх / любой с доступом к репозиторию может подписать «обновление».

## Решение

Ключ в репозитории. `build.sh` берёт `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` из окружения и только при их отсутствии использует встроенный ключ.

## Последствия

Положительные: личные обновления ставятся поверх и сохраняют данные.
Отрицательные: этим ключом нельзя подписывать APK для распространения посторонним. SHA-256 сертификата: `07:41:99:20:2a:17:17:31:de:ce:c4:25:f9:47:45:84:4d:9c:0b:2f:10:3a:81:76:b5:69:5d:bd:d0:b4:3a:ce`.
Что станет сигналом пересмотреть решение: первый APK, который ставит кто-то кроме автора, или публикация в любом магазине. Тогда генерируется новый ключ, хранится вне репозитория, а пользователи переходят через бэкап, удаление и установку.
