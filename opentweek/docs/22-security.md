# opentweek: безопасность

Актуальность: 27 сентября 2026 года.

## 1. Модель угроз

| Кто | Что хочет | Поверхность |
|---|---|---|
| Автор ICS-ленты или файла `.ics` | Выполнить скрипт в приложении, прочитать задачи | Поля `SUMMARY`, `DESCRIPTION`, `LOCATION`, `RRULE` |
| Отправитель ссылки `#share=` | Подсунуть задачу или скрипт | JSON внутри фрагмента |
| Автор подложного файла бэкапа | Заменить данные, внедрить скрипт через имя или тип вложения | `importBackup()` |
| Держатель ключа из репозитория | Выпустить «обновление», которое встанет поверх и прочитает данные | `android/opentweek.keystore` |
| Другое приложение на телефоне | Прочитать данные, вызвать мост | Экспортируемые компоненты, Intent |
| Сеть | Подменить ICS-ленту | HTTP-лента без TLS |
| Любое приложение на телефоне | Засыпать календарь задачами | `ACTION_SEND` и `AUTO_SEND` в `MainActivity` |

## 2. Слои защиты

1. React выводит весь пользовательский и внешний текст как текст. `dangerouslySetInnerHTML`, `eval`, `new Function` в коде запрещены.
2. Мост принимает только данные (строки, числа), не код. Методы перечислены в `20-architecture.md`, раздел 5.1. Новый метод требует записи в этот документ.
3. `WebView`: `setAllowFileAccess(false)`, `setAllowContentAccess(false)`, `usesCleartextTraffic="false"`. Навигация на чужие хосты уходит во внешний браузер (`shouldOverrideUrlLoading`), поэтому внешняя страница никогда не получает `OpenTweekNative`.
4. Компоненты Android: наружу открыта только `MainActivity` с `MAIN/LAUNCHER`; `ReminderReceiver` и `BootReceiver` имеют `exported="false"`; `PendingIntent` создаются с `FLAG_IMMUTABLE`.
5. `fetchText` принимает только `http(s)://` и обрывает ответ больше 8 МБ.

## 3. Классы риска операций

| Уровень | Примеры | Политика |
|---|---|---|
| L0 | Просмотр, поиск, экспорт JSON и ICS, печать | Автоматически |
| L1 | Создание, правка, отметка, перенос задачи; подписка на ленту; задача из голоса или «Поделиться» | Автоматически; после создания тост с «Открыть» |
| L2 | Удаление задачи или серии | Сразу, тост «Отменить» 5 с |
| L3 | Удаление списка или календаря вместе с задачами | `confirm()` с именем и числом задач |
| L4 | Восстановление бэкапа: полная замена данных | `confirm()`; рекомендация сначала сделать экспорт (runbook, раздел 7) |

Соло-вариант «второго подтверждения» для L4: перед восстановлением на телефоне сначала выгрузить текущий бэкап. Если восстановление окажется ошибкой, этот файл вернёт всё назад.

## 4. Недоверенные данные

Поля, которые приходят извне и никогда не интерпретируются как код или разметка:

```text
ICS:    SUMMARY, DESCRIPTION, LOCATION, RRULE, UID, DTSTART/DTEND, STATUS
share:  tasks[].title, note, date, color, subtasks[].title, rrule
intent: EXTRA_TEXT, EXTRA_SUBJECT (обрезаются до 2000 символов), результат распознавания речи
backup: весь JSON, включая attachments[].name, type, dataUrl
```

Правила обращения:

- `color` из шаринга подставляется в имя CSS-класса. Допустимы значения только из `COLORS`; T-114 добавляет проверку при импорте.
- `rrule` из импорта попадает в `rrulestr()`. Ошибка разбора даёт `null`, и задача ведёт себя как разовая (`buildRule`).
- `dataUrl` вложения проходит через `fetch(dataUrl)` при восстановлении бэкапа. Допустимы только `data:` URL; T-115 добавляет явную проверку схемы, сейчас её нет.
- Имя вложения показывается как текст и передаётся в `download` или `EXTRA_TITLE`, но не используется как путь.

## 5. Секреты

Серверных секретов нет. Единственный секрет — ключ подписи.

- Где: `android/opentweek.keystore`, пароль `opentweek`, алиас `opentweek`. Лежит в репозитории намеренно (ADR-0006).
- SHA-256 сертификата: `074199202a171731decec425f94745844d9c0b2f103a8176b5695dbdd0b43ace`.
- Ротация при переходе к публичному распространению (около 5 минут):

```bash
cd opentweek/android
keytool -genkeypair -keystore ~/opentweek-release.jks -alias opentweek-release \
  -keyalg RSA -keysize 3072 -validity 10000
KEYSTORE_FILE=~/opentweek-release.jks KEYSTORE_PASSWORD=... KEY_ALIAS=opentweek-release KEY_PASSWORD=... ./build.sh
```

Новый ключ хранится вне репозитория. Существующие установки перейдут на него только через бэкап, удаление и установку: Android сравнивает сертификат при обновлении.  
https://developer.android.com/studio/publish/app-signing

## 6. Аудит

Журнала операций нет: однопользовательское локальное приложение. Для разбора проблем используются:

- поле `updatedAt` каждой задачи;
- экспорт JSON как снимок состояния;
- на Android: `adb logcat -s chromium:V AndroidRuntime:E` — ошибки JavaScript и падения Java.

## 7. Что запрещено передавать внутрь

- JavaScript-код или имена функций через мост;
- пути файловой системы: только системные диалоги выбора;
- схемы URL, кроме `http`, `https` в `fetchText` и `data` во вложениях бэкапа;
- HTML в любых текстовых полях задачи.
