# Preview 1.6.0: calendar, journal and dictation usability

The user's personal **UI/UX Pro Max** skill was read from `/Users/dkatalshov/.agents/skills/ui-ux-pro-max/SKILL.md`, including its quick reference and mobile delivery rules. Local searches covered a productivity-app design direction, unobscured keyboard focus, and React form/dialog focus. The flat, restrained app style and relevant accessibility guidance fit OpenTweek; the generated marketing-page pattern did not, so it was not adopted or persisted. Existing bundled Montserrat/Comfortaa fonts remain offline. No packages or external services were added.

The audit used synthetic browser screens of Preview 1.5.0 at phone and desktop sizes plus the previously supplied phone references. Private images, video and diary text are not included in source or test fixtures. Key problems were small touch targets, crowded controls, low-contrast helper/selected text, visually reordered journal markup, repeated dates, voice explanations above writing, and a popup whose actions could leave a short viewport.

## Design and interactions

- Shared semantic theme tokens supply readable light/dark surfaces, foregrounds, focus rings and accent-label colors. A shared appearance hook also applies the user's existing local theme/font preferences in the popup. Selected action labels are checked at 4.5:1 across all nine existing accents in both themes.
- Calendar/Journal navigation has one shared date. The period, Today/previous/next and Week/Month controls have their own consistent toolbar. Journal hides unrelated calendar tools; task completion visibility remains available in existing Settings. Mobile main controls use 48px targets and 8px gaps. Compact month dates also fit the 320px viewport; at 375px the date targets are at least 48px wide.
- The week keeps its existing tasks, drag behavior and storage. Clearly labeled task-add lines, visible mobile completion/details actions and separated day surfaces make actions discoverable. The mobile month shows dates and item counts instead of tiny editable task rows; tapping a date opens the existing week/detail view. Desktop retains its full month content. Printing retains the period/year heading.
- The journal editor comes first in both the DOM and mobile visual order, with existing entries on the desktop right. Save, feedback and discard follow the main text so a short entry can be finished before optional guidance, mood and voice information. Controls remain in normal flow rather than a sticky bar covering focused fields. The duplicate date field is removed. A collapsed dictation-destination disclosure is shown only when local voice is available; guided destination locking is unchanged.
- Active cross-app voice shows microphone state, time left and Stop rather than repeating the full setup copy. Inactive setup still explains continuous microphone/battery use and requires explicit session consent; permission boundaries remain available before activation. No service, duration, wake phrase, permissions, model or restart behavior changed.
- The small diary popup shares theme/fonts, reports recording/review state, scrolls fields independently, and keeps Finish/Save/Cancel in a visible action region for short keyboard-like viewports. Committed fields and acknowledgement-only retry remain unchanged. Errors scroll into the field region without stealing focus. The native header retains brand and whole-session Stop; duplicate native Cancel was removed because capture Cancel is in the popup.

## Verification and boundaries

Validation covers TypeScript, lint (the pre-existing TaskModal warning remains), 113 unit tests, 39 browser E2E scenarios, six native test groups and the signed APK build. Added browser coverage exercises quick add/completion/month navigation, 320/375px phone, 812x375 landscape, tablet and desktop, dark appearance, 140% local font setting, reduced motion, small popup review/recording, measured action-label contrast and print context. Existing journal/date/draft/link/recovery/consent/cancellation/duplicate-save tests remain in the full suite.

Independent source review identified checkbox CSS specificity, lost print context and selected/danger contrast; those were corrected and re-reviewed. Synthetic screenshots were visually inspected. This does not establish complete screen-reader conformance, physical Android font/keyboard behavior, or wake reliability on a Pixel. Actual-device overlay editing, permissions, battery use and microphone quality still need acceptance. The unchanged voice acceptance checklist remains in `47-overlay-voice.md`.

No IndexedDB schema, diary write queue, draft/entry migration, linked-event identity, recurrence, date/timezone, feeds, sync, export format or microphone permission policy changed. This Preview uses the existing `app.opentweek.preview` identity and signer, so it should be updated over the existing Preview without uninstalling it. GitHub CI must be reported separately if the account billing block still prevents execution.
