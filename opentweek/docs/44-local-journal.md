# Локальный дневник и русская диктовка — 1.2.0

## Что работает

Кнопка «Дневник чувств» открывает отдельные записи с датой, текстом и необязательной самооценкой 1–5. Диктовка в Android дополняет черновик, не создаёт запись автоматически. «Сохранить запись» сохраняет, повторное нажатие обновляет ту же запись. Настроение не определяется алгоритмом и не является диагнозом.

Кнопка голосовой задачи и Android-ярлык теперь открывают редактор с тем же локальным распознавателем; задача создаётся после явного подтверждения. Старые Android RecognizerIntent и браузерный Web Speech путь удалены. В браузере/PWA дневник доступен для ручного ввода; локальной браузерной STT в этой версии нет.

## Установка модели и запись

1. В Android откройте дневник и нажмите «Скачать русскую модель». Это единственный сетевой запрос голосового модуля. Источник: https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip, Apache-2.0.
2. Архив: 46 236 750 байт, SHA256 `961d5ff98a17f4aa6de69864d0aa71fa5bac682301d2b5d17a3f24c5c99a46d4`. Распаковано 91 289 240 байт; временно нужны архив и распакованная копия. Установка атомарная, загрузку можно отменить.
3. Нажмите «Диктовать по-русски» и при желании разрешите микрофон в системном диалоге. Отказ не вызывает облачный fallback.
4. Нажмите «Остановить и вставить текст», исправьте распознавание и сохраните запись. Можно диктовать повторно для продолжения. «Отменить диктовку» отбрасывает только текущую диктовку.

Распознавание: Vosk Android 0.3.75, JNA 5.18.1, 16 kHz mono PCM в RAM. Аудиофайл не создаётся. Запись заканчивается вручную, после трёх секунд без нового частичного результата после завершённого речевого сегмента, после 15 секунд без распознанной речи или через 120 секунд. Это простое оконечное определение речи Vosk, а не отдельная нейросетевая VAD.

Режим только при открытом приложении: `onStop` отменяет запись. Нет foreground service, фонового ожидания, включения на загрузке телефона или постоянно слушающего микрофона. Для паузы нужно остановить диктовку, затем запустить снова. На экране различаются подготовка, запись с таймером, обработка и выключенный микрофон. Системное уведомление фоновой службы не требуется, потому что фоновой службы нет.

## Почему «эй, Твик» ещё не включено

На настоящей модели проверен `vosk_model_find_word`: `эй = 224198`, `твик = 18523`. Оба слова есть. Проверка словаря не является проверкой wake detector: не измерены ложные срабатывания, пропуски, шум/ТВ, расход батареи. Нельзя выдавать такую кнопку за надёжную.

Следующий этап: ограниченная грамматика с негативным/unknown вариантом, независимый набор записей фразы и похожих фраз, измерение false accepts/hour и recall, затем добровольно включаемая Android microphone foreground service с уведомлением/остановкой и проверкой правил запуска. Постоянный Whisper-декодер не нужен. Сейчас wake toggle отсутствует.

## Данные и резервные копии

Dexie schema v2 добавляет `journalEntries`, сохраняя прежние таблицы. JSON export v2 включает дневник; import v2 заменяет его после проверки всех записей. Import v1 заменяет планировщик и сохраняет текущий дневник. Миграция и импорт выполняются транзакционно; повторный save использует один id.

Текст хранится локально без дополнительного шифрования приложения. Экспорт JSON читается любым получателем файла. Существующее `android:allowBackup=true` оставлено: системная копия Android может содержать записи. Модель лежит в no-backup-каталоге. Не синхронизируется автоматически. Несохранённый черновик находится в памяти интерфейса и может исчезнуть при завершении процесса — это явно указано в редакторе.

## Сборка

`android/build.sh` теперь вызывает `build-local.sh`: старого API23/javac-пути недостаточно для JNI. Нужны Node/npm, JDK17+, Android SDK platform35/build-tools35.0.0. После `npm ci`:

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
sdkmanager 'platforms;android-35' 'build-tools;35.0.0'
./android/build.sh
```

Пути выше — параметры вашей установленной среды; скрипт завершится с понятной ошибкой, если они не настроены. Зависимости Maven загружаются с проверкой фиксированных SHA256; модель не включается в APK/Git. В APK четыре ABI: arm64-v8a, armeabi-v7a, x86, x86_64. Проверены ELF LOAD alignment >=16KiB для arm64/x86_64 обеих библиотек, zipalign и APK signature v2/v3. Пакет `app.opentweek`, origin `https://app.opentweek.local`, minSDK24/targetSDK34 сохранены.

Выход: `android/build-local/opentweek-1.2.0-local-debug.apk`, отдельная debug-подпись; `aligned.apk` — неподписанный выровненный APK для владельца release-подписи. Исходный `opentweek.keystore` не используется и не читается. **Debug APK не обновляет приложение с другой подписью. Не удаляйте установленное приложение ради установки: это может стереть его IndexedDB.** Для обновления нужна подпись тем же ключом, что установленный APK, и резервная копия. Сборка релизной подписи здесь не выполнялась.

## Проверка

- `npm test`: миграция старой базы, отдельность дневника, повторные save, валидация, rollback, v1/v2 backup, отменённые/дублированные voice events, отказ permissions и отсутствие fallback.
- `npm run test:e2e`: браузер с поддельным Android-мостом, без реального микрофона; редактирование/перезапуск, явное сохранение, отмена/поздний ответ, permissions, загрузка модели, задачи, защита от потери черновика при voice shortcut, мобильная ширина.
- `./android/test.sh`: traversal, абсолютные/дублированные пути, неполная модель, предел числа файлов/объёма ZIP, отмена распаковки.
- `npm run lint`, `npm run build`, APK compile/D8/signature/alignment. Root workflow `.github/workflows/opentweek.yml` запускает эти проверки и сохраняет debug APK как CI artifact; результат удалённого CI надо смотреть отдельно.

Не выполнены на устройстве: фактический захват микрофона, разрешение/отказ Android, качество русского STT, работа после авиарежима, блокировка экрана, звонки, Bluetooth, расход батареи, восстановление после убийства процесса. Код не заменяет эти проверки. Для первой проверки после корректной подписи: скачать модель, отключить сеть, продиктовать короткий неперсональный текст, отредактировать, сохранить, перезапустить и убедиться, что запись одна. Затем проверить отмену записи без сохранения.
